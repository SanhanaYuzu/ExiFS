# ExiFS 性能架构：如何达到 NTFS 级性能

版本: 1.1 规划 · 状态: Active · 作者: Sanhana Studio (XHC)

> 结论先行：ExiFS v1.0 的**磁盘格式**已与 NTFS 同构（extent 分配、属性化元数据、
> B+树目录、日志预留）。要达到 NTFS 级**运行时性能**，缺口不在格式，在四个引擎：
> **多级 B+树目录**（v1.1 本次交付）、**日志组提交**（v1.1）、
> **写回缓存 + 延迟分配**（v1.2）、**内核态驱动**（v2.0 / ExiOS）。
> 本文给出每一层的量化设计与验收标准。

---

## 1. NTFS 性能机制拆解

| 机制 | NTFS 做法 | 性能收益 | ExiFS 现状 |
|---|---|---|---|
| Extent 分配 | run list，按簇连续分配 | 大文件元数据 O(run 数) 而非 O(块数) | ✅ 已实现 |
| B+树目录 | INDEX_ROOT→INDEX_ALLOCATION 多级 | 百万文件目录查找 O(log n) | ⚠️ v1.0 仅常驻小索引，**v1.1 补多级** |
| 日志 ($LogFile) | 组提交 + redo | 崩溃一致免全盘 fsck | ⚠️ 格式已预留，**v1.1 实现重放** |
| 延迟分配 | 缓存写、合并簇、惰性分配 | 小文件写放大 ↓90% | ❌ v1.2 |
| 懒惰提交 | 30s 内合并元数据刷盘 | 元数据 IOPS ↓ | ❌ v1.2 |
| 预读 | 顺序簇预取 | 顺序读吞吐 ×3-5 | ❌ v1.2 |
| MFT  zone 保留 | MFT 区连续预留 | 元数据访问局部性 | ✅ 已实现（16 簇起连续区） |
| Fixup USN | 每扇区 2 字节校验 | 撕裂写防护，零额外 IO | ✅ 已实现 |
| CRC64 全记录 | 每记录校验 | 静默损坏检测 | ⚠️ 软件 CRC64 慢，**v1.2 换 CRC32C（SSE4.2 硬件指令）** |
| 无全局锁 | 每文件/每目录锁 | 多线程读不互阻 | ❌ 驱动层 v1.2 |
| 常驻小文件 | <700B 存 MFT 记录内 | 小文件零数据 IO | ✅ 已实现 |

**结论：格式层 7/11 已就绪；性能层缺口集中在目录树深度、日志、缓存三件事。**

## 2. v1.1 交付：多级 B+树目录（本次实现）

### 2.1 结构

```
INDEX_ROOT (常驻, MFT 记录内, ~768B 可用)
   ├── "." ".." 永久驻留根
   ├── 叶子项: (MFT引用, FILE_NAME key)
   └── 指针项: (子节点VCN, 子树首key)  flags=0x01
        ↓
INDEX_ALLOCATION (INDX 记录, 4096B, ~3900B 可用)
   ├── 叶节点: 最多 ~44 个目录项
   └── 内部节点: 最多 ~44 个指针项
        ↓
   三层容量: 8 × 44 × 44 × 44 ≈ 680,000 文件/目录
```

### 2.2 关键决策

- **指针项用 VCN 而非 LCN**：`file_ref` 低 48 位存子节点 VCN，flags 0x01 标识指针。
  VCN→LCN 由 $INDEX_ALLOCATION 的 run list 统一映射，分裂时无需改父节点物理位置。
- **根永久驻留**：`.` `..` 与顶层指针常驻 MFT 记录，热目录少一次磁盘 IO。
- **叶子分裂策略**：中点分裂（n/2），父节点插入分隔指针；向上冒泡；
  根满则报 `EDQUOT`（v1.1 深度上限 4 层，约 68 万文件，超出即满足 99.99% 场景）。
- **顺序插入优化**：顺序 key 命中最右指针，分裂均在尾部，接近 O(1) 均摊。

### 2.3 查找复杂度

| 目录规模 | v1.0（线性） | v1.1（B+树） |
|---|---|---|
| 100 文件 | 100 次 key 比较 | ~3 次 |
| 10,000 文件 | 10,000 次（≈40KB 扫描） | ~4 次（3 次 IO） |
| 100,000 文件 | 不可用（超记录容量） | ~5 次（4 次 IO） |

## 3. v1.2 性能引擎：缓存与日志

### 3.1 页缓存 + 延迟分配（驱动态）

```
write() → 页缓存(脏页, 按文件聚合)
   ↓ 30s / 脏页>25% / fsync
合并相邻脏区 → 一次性分配连续 extent → run list 追加合并 → 异步刷盘
```

- **分配合并**：`writeback` 时把物理连续的请求并成单个 run，run list 长度 ↓，
  MFT 记录更新次数 ↓（NTFS 同款）。
- **元数据惰性合并**：size/mtime 在缓存合并，刷盘时只写最终值，
  消除 NTFS 也头疼的“每 write 一次 mtime 落盘”。

### 3.2 日志组提交 ($LogFile)

```
事务开始 → REDO 记录追加(顺序写, 128KB 环形区)
   ↓ 组提交阈值: 32 个事务 或 100ms
一次 fsync 刷 COMMIT + 所有 REDO  → LSN 推进
```

- 崩溃恢复：扫到最后 COMMIT，向前重放 REDO——**分钟级恢复 vs fsck 全盘扫描**。
- 组提交把 N 次事务的 IOPS 合并为 1 次顺序写，随机写吞吐 ↑10×。

### 3.3 校验函数替换

CRC64 软件实现 ~300MB/s，SSD 上成为热点路径瓶颈。
v1.2 起：记录校验改 **CRC32C**（Castagnoli，SSE4.2 `crc32` 指令 ~20GB/s），
格式字段不变（`checksum` 字段宽 64 位，CRC32C 结果零扩展存入）。

### 3.4 无锁读路径

- 每目录一把 rwsem，每文件一把 rwsem；**读操作不加全局锁**。
- MFT 记录缓存（LRU, 16K 条）+ INDX 节点缓存（LRU, 4K 节点），
  热路径 `lookup` 纯内存操作，与 NTFS 的 MFT 缓存同构。

## 4. v2.0：自研内核 ExiOS 集成设计

> "到时候再写一个系统内核" —— 这是路线图，不是本期交付。
> 先冻结接口设计，保证 ExiFS 格式不被内核需求绑架。

### 4.1 分层

```
┌─────────────────────────────────────────┐
│  用户态  shell / 应用 (ExiFS API)        │
├─────────────────────────────────────────┤
│  VFS 层   vnode / dentry / 文件描述符    │  ← 自研内核 ExiOS
├─────────────────────────────────────────┤
│  ExiFS 驱动 (内核态)                     │  ← 本文格式的 C 实现迁入
│   · MFT 缓存 · B+树 · run list · 日志    │
├─────────────────────────────────────────┤
│  块层  bio (64KB 聚合) / 调度器          │
├─────────────────────────────────────────┤
│  驱动  NVMe / AHCI / VirtIO-blk          │
└─────────────────────────────────────────┘
```

### 4.2 内核侧接口冻结（v1.1 起不得破坏）

| 接口 | 语义 |
|---|---|
| `exifs_mount(dev, flags)` | 读 VBR→校验 CRC→加载 MFT 区→回放日志 |
| `exifs_lookup(vnode, name)` | B+树下降，返回子 vnode |
| `exifs_read(vnode, off, len)` | run list→bio 聚合→页缓存 |
| `exifs_write(vnode, off, len)` | 页缓存脏页→延迟分配→组提交 |
| `exifs_sync(vnode)` | 强制刷盘 + 日志 COMMIT |

### 4.3 内核开发顺序（ExiOS）

1. **Boot + 长模式 + 内核态 C 运行时**（约 3000 行）
2. **物理/虚拟内存管理**（PMM 位图 + 分页 + slab）
3. **VirtIO-blk/NVMe 驱动 + bio 层**
4. **ExiFS 驱动迁入**（本文 C 代码即为此准备：纯 `read/write/pread` 抽象，无 libc 依赖）
5. **VFS + 进程 + 系统调用**
6. **shell + 自举**（从 ExiFS 分区启动，闭环）

### 4.4 性能验收标准（v2.0）

| 指标 | 目标 | 测量法 |
|---|---|---|
| 小文件创建 | ≥ NTFS 90% | 10万次 create+close 计时 |
| 顺序读吞吐 | ≥ 磁盘带宽 85% | 1GB 顺序读 |
| 随机 4K 读 IOPS | ≥ NVMe 标称 70% | fio 对标 |
| 目录查找 (10万文件) | < 50μs | 微基准 |
| 崩溃恢复 | < 5s（任意卷） | 断电注入 + 计时 |
