# ExiFS 磁盘格式规范 (ExiFS On-Disk Format Specification)

版本: 1.0 · 状态: Draft · 作者: Sanhana Studio (XHC)

ExiFS 是一款自研文件系统，设计思想对标 NTFS：一切皆文件、元数据即数据、
B+树目录索引、位图分配、预写日志。所有多字节整数为**小端**，所有时间戳为
**1601-01-01 UTC 起算的 100ns 间隔**。

---

## 1. 卷几何 (Volume Geometry)

| 概念 | 默认值 | 说明 |
|---|---|---|
| 扇区大小 | 512 B | 固定 |
| 簇大小 | 4096 B (8 扇区) | 可配置，必须为 512 的 2 的幂 |
| MFT 记录 | 1024 B | 固定 |
| 索引记录 | 4096 B | 固定 |

### 1.1 区域布局

```
cluster 0 ─────────────────────────────────
    VBR (卷引导记录/超级块, 512B) + 保留
cluster 1 ~ 15                            系统保留区
cluster 16 ~ 16+Z-1                       MFT 区 (Z=1024 条记录预留区,
                                          16 簇起连续, 初始启用 64 条)
  16+Z                                      MFT 镜像 (前 4 条记录, 4KB)
  +1 ~ +32                                  $LogFile (128 KB)
  +33                                       $Bitmap (1 簇)
  +34 ~ +65                                  $UpCase (128 KB, 64K 个 UTF-16)
  +66 ...                                   数据区 (Data Region)
```

MFT 区按 1024 条记录**预留**（mkfs 时分配并标记已用），初始启用 64 条；
文件数增长时**就地倍增扩展**（64→128→256→512→1024），只需更新 VBR 记录数、
$MFT 的 real_size 与 CRC，无需搬迁——元数据访问保持连续局部性。

## 2. VBR / 超级块 (512 B, 扇区 0)

| 偏移 | 大小 | 字段 |
|---|---|---|
| 0x00 | 3 | 跳转指令 `EB 52 90` |
| 0x03 | 8 | OEM 名 `"EXIFS   "` |
| 0x0B | 2 | 每扇区字节数 (512) |
| 0x0D | 1 | 每簇扇区数 (2 的幂) |
| 0x0E | 2 | 保留扇区数 (0) |
| 0x14 | 8 | 总扇区数 |
| 0x1C | 8 | MFT 起始簇 (LCN) |
| 0x24 | 8 | MFT 镜像起始簇 |
| 0x2C | 8 | 日志区起始簇 |
| 0x34 | 8 | 数据区起始簇 |
| 0x3C | 4 | MFT 记录大小 |
| 0x40 | 4 | 索引记录大小 |
| 0x44 | 2 | 卷状态标志 (0x1=dirty, 0x2=mounted) |
| 0x46 | 2 | 版本 (0x0100 = 1.0) |
| 0x48 | 8 | 卷序列号 |
| 0x50 | 64 | 卷标 (UTF-8) |
| 0x90 | 16 | 卷 UUID |
| 0xA0 | 8 | MFT 记录总数 |
| 0xA8 | 8 | CRC64(0x00..0xA7) |
| 0x1FE | 2 | 引导签名 0xAA55 |

卷尾扇区存放 VBR 备份 (`$Boot` 文件 0 号记录指向)。

## 3. MFT 记录 (1024 B)

### 3.1 记录头 (48 B)

| 偏移 | 大小 | 字段 |
|---|---|---|
| 0x00 | 4 | 魔数 `"FILE"` |
| 0x04 | 2 | fixup 数组偏移 |
| 0x06 | 2 | fixup 项数 (= 扇区数 + 1) |
| 0x08 | 8 | $LogFile 序列号 LSN |
| 0x10 | 2 | 记录序列号 (删除时 +1) |
| 0x12 | 2 | 硬链接计数 |
| 0x14 | 2 | 首个属性偏移 |
| 0x16 | 2 | 标志 (0x1=使用中, 0x2=目录) |
| 0x18 | 4 | 已用字节数 |
| 0x1C | 4 | 分配字节数 |
| 0x20 | 8 | 基记录引用 (扩展记录用) |
| 0x28 | 2 | 下一属性 ID |
| 0x2C | 4 | 记录号 |

### 3.2 Fixup 机制

每条 MFT/INDX 记录的每个 512B 扇区末尾 2 字节写入 USN 序号，
原值存入 fixup 数组 (usa[1..n])。读取时校验并还原，写回时重新生成。
这是 NTFS 的经典“撕裂写”防护。

## 4. 属性系统

### 4.1 属性头

常驻 (resident, 24 B):

| 偏移 | 大小 | 字段 |
|---|---|---|
| 0x00 | 4 | 类型 |
| 0x04 | 4 | 属性总长 |
| 0x08 | 1 | 0=常驻 |
| 0x09 | 1 | 名称长度 (UTF-16 字符) |
| 0x0A | 2 | 名称偏移 |
| 0x0C | 2 | 标志 (0x1=压缩, 0x4000=加密, 0x8000=稀疏) |
| 0x0E | 2 | 实例标签 |
| 0x10 | 4 | 值长度 |
| 0x14 | 2 | 值偏移 |
| 0x16 | 1 | 是否被索引 |

非常驻 (non-resident, 头共 72 B)：在常驻头 0x18 之后追加

| 偏移 | 大小 | 字段 |
|---|---|---|
| 0x18 | 8 | 起始 VCN |
| 0x20 | 8 | 结束 VCN |
| 0x28 | 2 | run list 偏移 |
| 0x30 | 8 | 分配大小 |
| 0x38 | 8 | 真实大小 |
| 0x40 | 8 | 已初始化大小 |

### 4.2 属性类型

| 类型 | 名称 | 说明 |
|---|---|---|
| 0x10 | $STANDARD_INFORMATION | 时间戳/DOS 属性/USN |
| 0x30 | $FILE_NAME | 文件名 + 父目录引用 |
| 0x60 | $VOLUME_NAME | 卷标 |
| 0x70 | $VOLUME_INFORMATION | 版本/标志 |
| 0x80 | $DATA | 文件数据 (未命名=主数据流) |
| 0x90 | $INDEX_ROOT | 目录 B+树根 (常驻) |
| 0xA0 | $INDEX_ALLOCATION | 目录 B+树叶节点 (非常驻) |
| 0xB0 | $BITMAP | 索引/簇位图 |

### 4.3 $FILE_NAME 值布局 (62 B + 名称)

`parent_ref(8) | ctime(8) | mtime(8) | rtime(8) | atime(8) | alloc(8) | real(8) | flags(4) | name_len(1) | namespace(1) | UTF-16LE 名称`

parent_ref 低 48 位 = MFT 记录号，高 16 位 = 序列号。

### 4.4 $DATA run list

数据以“数据段 (run)”描述，每段: 头字节 (低 4 位=长度字段字节数，
高 4 位=偏移字段字节数) + 长度(簇数, LE) + 有符号偏移(相对前一段的 LCN 增量)。
偏移字段为 0 表示稀疏段。`0x00` 结束。

## 5. 目录索引 (B+树, v1.1 已实现)

### 5.1 $INDEX_ROOT (常驻属性值)

`indexed_type(4)=0x30 | collation(4)=1 | entry_size(4) | clusters_per_rec(1)+pad(3)`
后接索引头: `entries_off(4) | index_len(4) | alloc_len(4) | flags(4)`
flags 0x01 = 小索引 (全部常驻)。

### 5.2 索引项 (12 B + key)

`file_ref(8) | key_len(2) | flags(2) | key(FILE_NAME 值)`
flags: **0x01=子节点指针**(此时 file_ref 低 48 位 = 子节点 **VCN**，非 MFT 号),
0x02=末项。根索引必含 `.` 与 `..` 两项，且永久驻留根记录。

### 5.3 多级结构与容量

```
INDEX_ROOT (常驻, ~626B 可用)
   ├── "." ".." (永久驻留)
   └── 指针项: (子节点VCN, 子树首key)
        ↓
INDEX_ALLOCATION (INDX 记录, 4096B, ~3900B 可用)
   ├── 内部节点: 纯指针 (~43 个)
   └── 叶节点: 纯数据项 (~43 个)
```

- 小索引→大索引转换: 用户项整体移入 leaf 0，根只留 `.` `..` + 1 指针。
- 叶满则**中点分裂**，父节点插入分隔指针，向上冒泡；
  **根分裂只切指针**，`.` `..` 永不离开根。
- 容量: 根 ~7 指针 × 内部 ~43 指针 × 叶 ~43 项 ≈ 三层 1.3 万 / 四层 55 万文件。
- 删除: 从叶中移除（空叶写回空节点，防幽灵项）；v1.1 不做节点回收与再平衡。

### 5.4 $INDEX_ALLOCATION

非常驻属性，run list 按节点顺序覆盖各 INDX 记录
(每节点占 `INDEX_REC_SIZE/cluster` 个簇)。`real_size` = 节点数 × 4096。
INDX 记录头: `"INDX" | usa_off(2)=0x28 | usa_count(2)=9 | lsn(8) | vcn(8) | 索引头(16B)`，
条目自 0x40 起。

### 5.5 排序规则

按 (UTF-16 名字, namespace) 比较——UTF-16LE 字节序即码点序。

## 6. 位图与日志

### 6.1 $Bitmap

每簇 1 位，LSB 优先。位 1 = 已分配。元数据区+已用数据区置 1。

### 6.2 $LogFile (WAL)

记录头 40 B: `"EXILOG  " | lsn(8) | prev_lsn(8) | type(4) | data_len(4) | crc64(8)`
type: 1=START, 2=COMMIT, 3=REDO, 4=UNDO。
崩溃恢复: 从最后一条 COMMIT 向前重放 REDO。

## 8. 与 NTFS 的差异

| 维度 | NTFS | ExiFS |
|---|---|---|
| 定位 | 闭源, 微软维护 | 开源自研, 规范透明 |
| 大小写 | Win32 不敏感 | POSIX namespace 可选敏感 |
| 属性 | 13+ 种内置 | 同构子集, 无 EFS/压缩内置 |
| 定位目标 | 通用桌面/服务器 | 学习研究 + 可嵌入的轻量自研格式 |

完整结构定义见 `include/exifs.h`；参考实现见 `tools/exifs_ref.py`。
